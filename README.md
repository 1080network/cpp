# Mica SDK for C++

A C++ client library for the [Mica](https://mica.io) network. Mica's API is [gRPC](https://grpc.io) over mutual TLS.

## Built from the protos, against your protobuf and gRPC

Unlike the other Mica SDKs, this repository does not contain generated code. C++ generated code only compiles against the
exact protobuf version that produced it, so one set of generated sources cannot serve every client. Instead this
repository ships the [public protos](https://github.com/1080network/proto) (in `protos/`) and CMake generates the code
when you build, with **your** installed protobuf and gRPC. Any recent protobuf and gRPC work; the SDK is tested against
the versions in the table at the end.

## Libraries

One CMake library per role, so you only build the roles you play:

| Target | Use it if you are |
| --- | --- |
| `Mica::issuer` | an issuer |
| `Mica::acceptor` | an acceptor |
| `Mica::common` | everyone: the shared messages, the member services (such as `Ping`) and `mica/sdk/mtls.h`. Linked automatically by the two above |

## Using it

You need CMake 3.21 or later, a C++17 compiler, and protobuf and gRPC installed with their CMake packages (for example
`apt install libgrpc++-dev libprotobuf-dev protobuf-compiler-grpc`, `brew install grpc protobuf`, or vcpkg's `grpc`).
Add the SDK to your project, for example with `FetchContent`:

```cmake
include(FetchContent)
FetchContent_Declare(mica_sdk GIT_REPOSITORY https://github.com/1080network/cpp.git GIT_TAG v2.0.0-pre0)
FetchContent_MakeAvailable(mica_sdk)

add_executable(my_app main.cc)
target_link_libraries(my_app PRIVATE Mica::issuer)   # or Mica::acceptor
```

Versions match the proto release (`v2.0.0-pre0`). The tests and examples are only built when this is the top-level project.

## Connecting

Mica uses mutual TLS. You need the root CA, and the client certificate and key Mica issued to you, as PEM files. The
server certificate is verified against the root CA and its host name, and the client presents your certificate.

```cpp
#include "mica/member/ping/v1/ping_service.grpc.pb.h"
#include "mica/sdk/mtls.h"

auto credentials = mica::sdk::MtlsCredentials::FromFiles("rootca.crt", "client.crt", "client.key");
auto channel = mica::sdk::CreateMtlsChannel("api.example.mica.io:443", credentials);
auto stub = mica::member::ping::v1::PingService::NewStub(channel);

grpc::ClientContext context;
mica::member::ping::v1::PingResponse response;
grpc::Status status = stub->Ping(&context, mica::member::ping::v1::PingRequest(), &response);
```

The channel works with any generated client, for example `mica::issuer::service::v2::IssuerToMicaService::NewStub(channel)`
(`#include "mica/issuer/service/v2/issuer_to_mica_service.grpc.pb.h"`).

`examples/ping.cc` is a complete program that connects and calls `Ping`, a good first check that your certificates and
network path work:

```bash
cmake -S . -B build && cmake --build build
build/mica_ping api.example.mica.io:443 rootca.crt client.crt client.key
```

## Repository layout

| Path | Contents |
| --- | --- |
| `protos/` | the protos the SDK compiles, copied from a proto release by `scripts/update-from-proto.sh` (`protos/.proto_commit` records the commit) |
| `include/mica/sdk/mtls.h` | hand-written mutual TLS helper |
| `tests/` | a real mutual TLS call to an in-process server, using certificates generated by `make-certs.sh` (needs the `openssl` command) |
| `examples/` | runnable examples |
| `scripts/update-from-proto.sh` | copies a proto release in, then builds and tests |

## Releasing (maintainers)

1. Run `scripts/update-from-proto.sh <version> <path to a checkout of the proto repository>` (the tag must exist there). It copies the protos in, sets the version, and builds and tests.
2. Open a pull request with the changes and merge it.
3. Tag the merge commit with the version (for example `v2.0.0-pre0`) and create a GitHub release. There is no package to publish: clients fetch the tag with CMake.
